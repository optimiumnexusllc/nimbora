## Overview

**Téléphonie d'entreprise** gives each company a complete PBX under your brand: extensions and SIP lines, queues, contact-center agents, IVRs, voicemail, conferences and call logs. You manage it from NIMBORA, and any of its numbers can ring an AI agent.

The PBX engine is [Wazo Platform](https://github.com/wazo-platform) (GPL-3.0), installed on a dedicated server and fully white-labelled. Companies, their staff and their phones only see your brand: the e-mails, the password-reset page, the SIP `User-Agent` and `Server` headers, and the server's landing page.

| From NIMBORA you can | How it works |
|---|---|
| See live calls and hang one up | PBX call-control API, refreshed every 10 seconds |
| See agents (available, on break, logged out) and pause, resume or log them out | PBX agent API |
| See queues, extensions and inbound numbers | PBX configuration API |
| Route a PBX number to an AI agent | NIMBORA creates the inbound number on the PBX and registers it on its side |
| Keep one customer history | Each human call on the PBX is added to the customer's history, next to AI calls, WhatsApp and web chat |
| Apply your brand to the PBX | Sets the SIP `User-Agent`/`Server` header to your PBX name |
| Create extensions, one by one or from a CSV file | User, line, extension, SIP account, voicemail, login and contact-center agent in one action |
| Create queues and choose their members | Ring strategy, ring time, agents |
| Send unanswered queue calls to an AI agent | Overflow after a wait you choose, when nobody answers or nobody is logged in |
| Apply the company's opening hours to numbers | Hours and closures from **Mon entreprise**; outside hours an AI agent, a voicemail, or hang up |

## Install the PBX

The kit in `deploy/pbx/` installs the latest stable engine on a dedicated Debian 12 server, applies the white label and creates a least-privilege service account for NIMBORA:

```bash
sudo ./install.sh --brand "NIMBORA" --nimbora-url https://app.example.com \
  --nimbora-ip 203.0.113.10 --company "Ivoire Immo"
```

The install script:

- generates every secret, so the installer's public default passwords are never used;
- leaves out the engine's own web UI;
- installs the supervision dialplan (`nimbora-supervision`, used to listen to calls from NIMBORA, reachable by API only);
- installs a deny-by-default nftables firewall: only SSH, HTTPS, SIP and RTP (`--sip-from`), the ARI (port 5039) from NIMBORA and, optionally, phone provisioning (`--phones-from`) are reachable; the AMI (port 5038), RabbitMQ, Postfix and the engine's internal services stay local to the server;
- creates the service account. Its policy grants only the 110 permissions NIMBORA uses (`deploy/pbx/integration-policy.json`), with no wildcard grant. After upgrading NIMBORA, run `deploy/pbx/scripts/create_service_account.py` again: it updates the policy in place, and the account keeps its password.

See `deploy/pbx/README.md` for every option and what the white label changes.

## Connect it

<Steps>
  <Step title="Give AI agents access">
    In **Téléphonie → Ajouter → Asterisk ARI**, enter the PBX's ARI endpoint (`http(s)://<pbx>:5039`), ARI user and password, and the WebSocket client name `nimbora`. These values are printed at the end of the install.
  </Step>
  <Step title="Connect the PBX">
    In **Téléphonie d'entreprise → Connexion**, enter the PBX address, the service account (`nimbora-integration`) and its password, the company's tenant, and the ARI configuration from step 1. NIMBORA checks the credentials, the tenant and the engine version right away.
  </Step>
  <Step title="Apply your brand and receive events">
    Click **Appliquer la marque** (SIP headers) and **Recevoir les événements** (the PBX sends the end of each call to NIMBORA through a webhook with a secret URL).
  </Step>
  <Step title="Route a number to an AI agent">
    In **Numéros**, click **Router un numéro vers un agent IA** and pick the agent. Callers to that number now reach the agent. A number that already has a destination on the PBX (extension, queue…) is never overwritten. **Retirer** removes the route from both the PBX and NIMBORA.
  </Step>
</Steps>

## Shared PBX of the platform (one tenant per company)

An operator can run **one PBX for all its client companies** instead of one server per company. Each company gets its own tenant on the shared PBX — extensions, queues, numbers, voice menus and recordings stay isolated — created by NIMBORA in one click, without any credential to type.

<Steps>
  <Step title="Install the PBX in operator mode">
    ```bash
    sudo ./install.sh --brand "NIMBORA" --nimbora-url https://app.example.com \
         --nimbora-ip 203.0.113.10 --company "Opérateur" --operator
    ```
    `--operator` also creates the **provisioning account** (`nimbora-provisioning`) in the top tenant. It holds the service account's rights plus those needed to create tenants, dialplan contexts and service accounts — nothing more (`deploy/pbx/provisioning-policy.json`). The settings to copy are printed at the end.
  </Step>
  <Step title="Configure the platform">
    In NIMBORA's `.env`:

    | Variable | Value |
    | --- | --- |
    | `PBX_PROVISIONING_URL` | `https://pbx.example.com` |
    | `PBX_PROVISIONING_USERNAME` / `PBX_PROVISIONING_PASSWORD` | the provisioning account |
    | `PBX_PROVISIONING_ARI_ENDPOINT`, `_ARI_USER`, `_ARI_PASSWORD`, `_ARI_WS_CLIENT` | the PBX's ARI, for AI agents |
    | `PBX_PROVISIONING_ON_SIGNUP` | `true` to create the tenant as soon as a company signs up |
    | `PBX_PROVISIONING_USER_RANGE` (and `_GROUP_`, `_QUEUE_`, `_CONFERENCE_RANGE`) | internal numbering of each tenant (default 1000-1999, 2000-2999, 3000-3999, 4000-4999, as the install kit) |
  </Step>
  <Step title="The company activates its telephony">
    In **Téléphonie d'entreprise**, **Activer la téléphonie** creates the tenant (`org<id>`), its internal, inbound and outbound contexts (internal calls can dial out), a service account restricted to the tenant with the integration policy, the ARI configuration of its AI agents (its own Stasis application on the shared Asterisk) and the events webhook. The connection is then **managed by the platform**: the company cannot see or change it. The operator can also do it from the super-admin API (`POST /api/v1/saas/admin/tenants/{id}/pbx/provision`) and remove a tenant (`DELETE …/pbx`, irreversible).
  </Step>
</Steps>

### Plans: shared PBX, own PBX and human seats

Two plan options decide what a company may use (super-admin console → Offres):

- **Téléphonie d'entreprise sur le PBX de la plateforme** (`pbx_shared`) — the one-click activation above.
- **Connexion de son propre PBX** (`pbx_dedicated`) — a dedicated server installed with the kit, connected from **Connexion**. Plans created before these options keep this right.

**Human seats** (`max_human_seats`) count the agents of the built-in contact center **and** the PBX extensions. Creating an extension beyond the plan is refused with the number of seats left; a CSV import creates the valid lines up to the seats left and lists the others. The PBX page shows **Postes 4 / 15**.

## Administer the PBX

### Extensions

**Postes → Nouveau poste** creates everything a person needs in one action, rolled back by the PBX if anything fails:

- the user;
- the line, with **Softphone dans le navigateur** (WebRTC) or **Téléphone de bureau ou application SIP**;
- the extension number;
- the SIP account, with a generated 20-character password;
- the voicemail, with a 6-digit PIN, messages sent by e-mail when an address is given;
- the login, which is the e-mail address or `poste<number>`, with a generated password;
- optionally the contact-center agent.

The credentials are shown **once**, so you can copy them or download them as a CSV file. NIMBORA never stores them. Later, **Mot de passe** e-mails the person a reset link under your brand. **Supprimer** removes the user together with their line, extension, voicemail and login.

### Importing a CSV file

**Importer (CSV)** reads a comma- or semicolon-separated file with these columns, up to 500 rows:

```text
prenom;nom;poste;email;ligne;messagerie;agent
Awa;Diallo;1010;awa@example.com;navigateur;oui;oui
Koffi;Yao;1011;;sip;non;non
```

Before anything is created, a preview checks every row and flags:

- missing first names;
- invalid extension numbers or e-mail addresses;
- extension numbers that already exist on the PBX;
- extension numbers used twice in the file.

Only the valid rows are created. A failed row never stops the others. You then download the credentials sheet for everyone who was created.

### Queues and AI overflow

**Files → Nouvelle file** creates a queue with its internal number, its ring strategy and its agents. The strategies are:

- all phones at once;
- the agent idle the longest;
- the agent with the fewest calls;
- each in turn;
- random;
- in list order.

**Membres** changes who takes the queue's calls.

**Débordement IA** hands callers to an AI agent in three cases: after the wait you choose (10 seconds to 1 hour), when nobody answers, or when no agent is logged in. No caller is left waiting. Behind the scenes, the queue's wait-time destination and its fallbacks point to `Stasis(<app>,inbound,called=nimbora-q<queue>)`. That key contains letters, so it can never collide with a real phone number.

### AI agent → PBX queue or extension, with the handoff card

The opposite way works too: an AI agent hands a caller to your people on the PBX. In a **Transfer call** tool, the destination picker lists **the PBX queues and extensions** (and the built-in contact center's queues). You can also type them:

| Destination | Where the caller goes |
|---|---|
| `pbx-queue:<id>` | A queue of the PBX, for example `pbx-queue:1` |
| `pbx-extension:<number>` | One person's extension, for example `pbx-extension:1001` |

To let NIMBORA choose at hand-off time (VIP customer, usual advisor, skill, language, who is free now), use the **Routage intelligent** tab of the tool instead. See [Smart routing](/contact-center/smart-routing).

The call enters the PBX's own dialplan (`Local/<number>@<context>` from the queue or extension, read on the PBX), as if a phone of the company had dialled it. Queue strategy, music on hold, agents, overflow and voicemail all apply. The person who answers sees:

- **on any phone**: the customer's number, with the name `IA · <customer>`;
- **in [NIMBORA Softphone](/integrations/telephony/softphone#calls-handed-over-by-the-ai)**, as soon as it rings: the AI's **handoff card**. It shows the reason, a three-sentence summary, the customer's mood, the suggested next step, the data collected and the conversation;
- **in [Supervision](/contact-center/supervision)**: an **IA** mark on the caller waiting in the queue, then the reason under the agent's call.

A supervisor can also take over a live AI call and send it to a PBX queue from the supervision console.

The transfer is allowed only when the AI call runs on the PBX's own Asterisk, that is, through the ARI configuration linked to the PBX connection. Dialling a PBX context on another Asterisk would reach nothing, or someone else. The queue number and context read from the PBX are checked before dialling. The card closes from the PBX's call logs: **answered** when a person took the call, **abandoned** otherwise. An abandoned card can be called back by an AI agent (see the next section).

### Missed calls called back by an AI agent

**Journal → Appels manqués rappelés par l'IA** (missed calls called back by the AI). A customer hung up before anyone answered? An AI agent calls them back, introduces itself on behalf of the company and picks up their request. You choose:

- the AI agent that calls back. Its context receives `callback_reason` and `customer_name`;
- which calls: customers who hung up **in a queue**, or **every unanswered inbound call** (extensions, groups, queues);
- the delay before calling back, and whether to wait for the **next opening** (**Mon entreprise** hours and closures).

Rules:

- Customers already served are left alone. When the PBX logs an answered call with them, in or out, before the callback, the callback is **canceled** ("Le client a été servi entre-temps").
- Several missed calls from one customer make one callback.
- Blocked numbers are never called.
- When the AI had handed the caller over and nobody answered, the callback carries the AI's card: its reason, its summary and the customer's name.

The callbacks are the platform's usual ones: the scheduler has the agent dial at the planned time, retries every 15 minutes (3 attempts), and records the outcome. The latest ones are listed under the setting.

This needs the PBX events (**Recevoir les événements**): each finished call reaches NIMBORA as a call log.

### Opening hours

**Numéros → Horaires** applies the opening hours and exceptional closures of **Mon entreprise** to the numbers you pick. Outside those hours, calls go to an AI agent (recommended), to a voicemail, or are hung up.

The PBX keeps a single schedule per company. When the hours change, open the dialog again and apply: the same schedule is updated. A number that already had another schedule switches to the company's.

### NIMBORA Softphone

**Postes → Softphone** pairs an extension with [NIMBORA Softphone](/integrations/telephony/softphone) on Windows, macOS, Linux, Android, iPhone or in the browser, with a one-time code or a QR code. **Postes → Softphones** lists the paired devices and revokes them.

### Supervision

**Supervision** shows the PBX live next to the AI calls: callers waiting in each queue, agents and their calls, conversations on every extension. From there, a supervisor can listen to, whisper to or barge into a call, and read queue and agent statistics (answered rate, service level, average wait). See [Live supervision](/contact-center/supervision#enterprise-pbx).

### Call groups

**Groupes → Nouveau groupe** gives several extensions one internal number. Choose how they ring:

- all at once;
- in list order (the order is set by moving members up and down);
- each in turn, or the one idle the longest;
- the one with the fewest calls, or at random.

**Sonnerie** is how long each extension rings. When members ring one after another, the group waits long enough for every member to ring once.

**Si personne ne décroche** sends the call on to an AI agent, a voicemail, a queue, an extension or a voice menu. AI agents take the call with `Stasis(<app>,inbound,called=nimbora-g<group>)`. **Membres** and **Sans réponse** change a group later.

The PBX accepts only unaccented letters in group names, so "Équipe accueil" is saved as "Equipe accueil".

Numbers, voice menu keys and fallbacks can all lead to a group.

### Forwards, do-not-disturb and unanswered calls

**Postes → Renvois** sets how one extension handles its calls:

- **Renvois**:
  - **Toujours** forwards every call;
  - **Si occupé** forwards when the extension is already on a call;
  - **Si pas de réponse** forwards after it has rung.

  The destination is a phone number or an extension.
- **Ne pas déranger**: the extension stops ringing.
- **Quand personne ne décroche**: where calls go when the extension does not answer, is busy or is unreachable. That can be a voicemail, a colleague, a queue, a group, a voice menu, or **an AI agent** that answers in the person's place and takes a message (`called=nimbora-u<user>`).

### Conference rooms

**Conférences → Nouvelle salle** creates a meeting room with an internal number. You can also set:

- a participant PIN and an organizer PIN (4 to 12 digits, and they must differ);
- a maximum number of participants;
- arrival announcements and recording.

PINs are never sent back by the API. To let outside callers dial in, point a public number at the room from **Numéros**.

While a meeting runs, each room lists who is in it and since when. Organizers are marked with a crown. You can mute, unmute or remove any participant. The list refreshes every 10 seconds while the tab is open.

### Voice menus

**Serveurs vocaux → Nouveau menu** opens a visual editor for menus like "for sales, press 1". Each menu has:

- an optional greeting;
- up to 12 choices, each one a key (0 to 9, `*`, `#`), a label, and a destination;
- a menu message, which NIMBORA writes from the choices if you leave it empty ("Pour le service commercial, tapez 1. Pour notre assistante, tapez dièse.");
- a message for keys that lead nowhere, how long to wait for a key, and how many tries;
- a destination for callers who press nothing or keep pressing wrong keys.

A choice can lead to a queue, a call group, an extension, a voicemail, a conference room, another menu, a hang-up, or **an AI agent**. Put an AI agent as the fallback and no caller hangs up without an answer.

The editor shows the menu as the caller lives it: the messages, the phone keypad with the keys in use, and where each key leads. **Écouter** plays any message in telephone quality before you publish.

**Publier** does the rest:

1. Every message is spoken with your organization's voice, or the voice of the agent you pick, so the menu sounds like your AI agents.
2. The audio is converted to the format the PBX plays natively (8 kHz, 16-bit, mono) and uploaded to the `menus-vocaux` sound category.
3. Each key becomes a PBX destination. AI keys hand the call over with `Stasis(<app>,inbound,called=nimbora-m<menu>-<key>)`. Like the queue overflow key, it contains letters and never collides with a phone number.
4. The PBX menu is created, or replaced if it already exists. Messages and AI hand-offs you removed are cleaned up.

A menu you change after publishing shows **Modifié, à republier** until you publish it again. A menu that another menu or a number still leads to cannot be deleted: change those first.

### Numbers

**Numéros → Ajouter un numéro** creates a public number on the PBX and chooses where it rings: an AI agent, a voice menu, a queue, an extension, a voicemail, or nowhere. **Destination** changes it later. The number keeps its schedule and caller ID settings; only the destination changes.

A number that already existed on the PBX can be handed to an AI agent too. NIMBORA remembers its previous destination: removing the AI agent puts it back, and never deletes the number.

### Operator lines and outbound routes

**Lignes opérateurs → Ajouter une ligne** connects the PBX to a telephone operator over SIP. Enter the operator's server, port and transport (UDP, TCP or TLS). Then pick how the line authenticates:

- **registration**: a SIP username and password. The PBX registers with the operator, using the tenant's registration template.
- **IP address**: no registration. The operator recognizes your PBX by its address, and the PBX recognizes the operator's calls by its host.

Calls from the operator arrive in the PBX's incoming-call context, so the numbers you route above ring. The list shows whether each line is registered and how many calls it carries. The SIP password is never sent back.

**Nouvelle route** decides which dialled numbers leave through which lines:

- **Lines in order**: the first is tried first, the next takes over if it fails.
- **Patterns**: `_` followed by `X` (any digit), `N` (2 to 9), `Z` (1 to 9), `[1-5]` (a range) and `.` (the rest of the number). Shortcuts fill in common patterns.
- **For each pattern**: digits to strip, a prefix to add for the operator, and the **number presented** to the people you call.

**Tester un numéro** shows which pattern a number matches and exactly what the operator receives, before anything reaches the PBX. A line used by a route cannot be deleted until you remove it from the route.

### AI agents calling out through the PBX

**Lignes opérateurs → Appels sortants des agents IA** sends AI calls through your PBX's lines and under your number. That covers campaigns, AI callbacks and test calls. Choose how the calls leave:

- **Par les routes sortantes**: calls go through your outbound routes, exactly like a call dialled from an extension. The routes' patterns, presented numbers and failover between lines all apply. The ARI dial string becomes `Local/{number}@<outcall context>`.
- **Par une ligne précise**: calls go straight to one operator line, bypassing the routes. The dial string becomes `PJSIP/{number}@<line endpoint>`.

AI calls use international numbers (`+2250707112233`). **Format du numéro composé** rewrites them for your operator:

| Format | `+2250707112233` becomes | `+33612345678` becomes |
|---|---|---|
| Unchanged | `+2250707112233` | `+33612345678` |
| `00` prefix | `002250707112233` | `0033612345678` |
| National (country code 225, empty prefix) | `0707112233` | `0033612345678` |

In national format, numbers from the country you set lose their country code and get the national prefix: empty for Côte d'Ivoire, `0` for France. Numbers from other countries are dialled with `00`. Transfers to outside numbers are rewritten the same way.

**Numéro présenté** becomes the ARI configuration's default caller ID. The card shows, before you save, exactly what an AI call will dial.

The same settings appear on the ARI configuration under **Téléphonie**, so editing it there keeps them.

### Call restrictions

**Lignes opérateurs → Restrictions d'appel** controls what each extension may dial. Common restrictions are one click away:

- no international calls (`_00.`, `_+X.`);
- no premium-rate numbers (`_08.`);
- internal calls only.

A restriction either **forbids** its patterns, or **allows only** them. An optional override PIN lets an extension make a forbidden call by typing the code. **Postes** changes which extensions the restriction applies to. The PIN is never sent back by the API.

### Blocked numbers

The organization's [blocked numbers](/configurations/blocked-numbers) apply to every call AI agents answer or place through the PBX: blocked callers are hung up before the agent answers, and opted-out people are never dialled.

### Recording human calls

**Enregistrements** sets which calls between customers and your staff are recorded, and what NIMBORA does with the files. AI calls are recorded by the agent run, as before.

**What the PBX records**:

- calls received from outside, calls placed to outside, and calls between extensions;
- on every extension, or only on the ones you tick.

**Appliquer** turns the engine's recording switches on or off on each extension. It only changes extensions whose settings differ.

<Warning>
Tell callers that calls may be recorded, for example in a voice menu's greeting. Recording rules depend on your country.
</Warning>

**What the platform does with the recordings**:

- **Copier les enregistrements**: each recording is copied to the platform's storage (MinIO or S3) when the call ends. The PBX's call-log webhook queues the copy, and a check every 10 minutes catches any that were missed (the last two days).
- **Transcrire les appels**: the copy is transcribed with your organization's own speech recognizer (self-hosted Whisper, OpenAI-compatible or Deepgram). Card numbers, CVV, IBAN and social security numbers are **always masked** in the stored text. Recognizers often mishear digits, so any run of 13 to 19 digits is masked as a card number even if it fails the card checksum. The other categories of your privacy policy are masked too when masking is on.
- **Retirer du PBX une fois copiés**: the recording is deleted from the PBX after the copy, so only one copy exists.

The list shows who called whom, when, the direction and the duration. You can search by number, name, or a word that was said (in transcripts). **Écouter** plays a recording through a link that expires after 15 minutes.

The privacy policy applies to these recordings:

- the **recording retention** period deletes them, files included;
- **erasing** a customer deletes their recordings;
- an **access request** lists them, with their transcripts.

### How AI calls flow

The route is a custom destination on the PBX: `Stasis(<app>,inbound,called=<number>)`. NIMBORA receives the call over ARI and treats it as inbound, even if the PBX already answered it. It finds the agent from the number named in the route, because inside the PBX's dialplan the dialed extension is often just `s`. The agent's audio then streams over the WebSocket client configured on the PBX.

### Human calls in the customer history

With events on, every finished call between a customer and your staff is added to the customer's history, for example "Appel entrant avec Koffi Yao (4 min)" or "Appel manqué". Agents read this history on every channel. A few calls are skipped:

- internal calls between extensions;
- calls to numbers answered by AI agents, which the agent records itself;
- deliveries the PBX repeats.

## Password resets under your brand

The engine's reset e-mail normally links to its vendor's web app. The kit replaces it with a French e-mail from your sender address, linking to `https://<your NIMBORA>/pbx-password`. That page sets the new password on the PBX. It only forwards to PBXs connected to NIMBORA: the host written in the link is used to pick one of them and is never contacted directly.

## Security

- **SaaS mode**: a PBX address that resolves to a private, loopback or link-local IP is refused, like HTTP tools. For the operator's own PBX on the internal network, add its host name to `PBX_ALLOWED_HOSTS`.
- The service account password is never sent back by the API (shown masked).
- Each organization sees and manages only its own PBX connection.
- Use HTTPS for ARI (`--ari-tls-cert`, `--ari-tls-key`) whenever NIMBORA reaches the PBX over the Internet.
