title: "Object storage"
description: "Where recordings and files are stored (SeaweedFS by default), why the bucket is private, and how to move an existing MinIO install to SeaweedFS or to a managed S3 service."
---

Call recordings, transcripts, knowledge-base documents and campaign files are stored in an S3-compatible object store. The platform bundles **SeaweedFS** (Apache-2.0, maintained); any S3 service can replace it.

| `OBJECT_STORE` | Store | When |
|---|---|---|
| `seaweedfs` (default) | Bundled SeaweedFS, reached as S3 at `http://seaweedfs:8333` | New installs |
| `minio` | Bundled MinIO, `minio` compose profile | Installs made before SeaweedFS became the default, until they migrate |
| — with `ENABLE_AWS_S3=true` | Any other S3 service (`S3_*` settings) | Managed storage; always wins over `OBJECT_STORE` |

The bundled store's keys are `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD` in `.env`, whichever store it is (the names are kept so every install script works unchanged). `GET /api/v1/health` returns `object_store`, and `legacy_minio_files` when files are still on MinIO while another store is active.

<Note>
**Updating an install made before.** The install and update scripts (`remote_up.sh`, `scripts/update_remote.sh`, `scripts/start_docker.sh`, the lab kit, `deploy/enterprise/install.sh`) find the existing MinIO volume and write `OBJECT_STORE=minio`: nothing changes until you migrate. If you run `docker compose up` by hand after updating, set `OBJECT_STORE=minio` and `COMPOSE_PROFILES=minio` in `.env` first — otherwise new files go to SeaweedFS and the old ones stay on a MinIO that is no longer started (the API logs it, and `/api/v1/health` shows `legacy_minio_files`).
</Note>

## A private bucket and signed links

The bucket is **private**. Every link handed to a browser — play a recording, open a transcript, upload a document — is a **signed URL that expires** (one hour for downloads, 15 minutes for uploads), computed for the address the browser will use.

<Warning>
Versions before this change made the bundled bucket readable, writable and **listable by anyone** reaching the public `/voice-audio/` path, and returned unsigned links. The API now removes that anonymous policy when it starts. If you ran an earlier version on a public server, update, and check your access logs for requests to `/voice-audio/` without an `X-Amz-Signature` parameter.
</Warning>

Requirements:

- `MINIO_PUBLIC_ENDPOINT` (or `PUBLIC_BASE_URL`) is the **public** address, scheme and host only (`https://app.example.com`). A link signed for `localhost` does not work from another computer.
- The reverse proxy in front keeps the **Host header** and the `/<bucket>/` path. nginx (`deploy/templates`), Caddy (`deploy/enterprise`) and Traefik (`deploy/lab`) do.

To close an exposed bucket right away, before updating:

```bash
docker exec minio mc anonymous set none local/voice-audio
```

## Leaving the bundled MinIO

MinIO removed its public images; the bundled one is the last open-source release, pinned and no longer updated. For production, move the files to a maintained S3 service (Scaleway Object Storage, OVHcloud, Cloudflare R2, Wasabi, AWS S3) or a self-hosted one (SeaweedFS, Garage).

<Steps>
  <Step title="Create the destination bucket">
    Private bucket, an access key limited to it. For uploads from the browser, allow `PUT` and `GET` from your platform's address in the bucket's CORS rules.
  </Step>
  <Step title="Configure the destination">
    In the API environment: `S3_BUCKET`, `S3_REGION`, `S3_ENDPOINT_URL` (outside AWS), `S3_ADDRESSING_STYLE=path` and `S3_SIGNATURE_VERSION=s3v4` for most S3-compatible services, `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY`. If the endpoint is only reachable internally (a self-hosted store behind your proxy), set `S3_PUBLIC_ENDPOINT_URL` to the address browsers use.
  </Step>
  <Step title="Copy, then verify">
    ```bash
    docker compose exec api python -m scripts.migrate_object_store copy --dry-run
    docker compose exec api python -m scripts.migrate_object_store copy
    docker compose exec api python -m scripts.migrate_object_store verify
    ```
    The copy skips objects already at the destination with the same size: run it as often as needed, the last run just before switching copies only what was added since. `verify` fails if an object is missing or has a different size.
  </Step>
  <Step title="Switch">
    ```bash
    docker compose exec api python -m scripts.migrate_object_store switch   # type BASCULER
    ```
    Files stored on MinIO now point to the S3 backend. Set `ENABLE_AWS_S3=true` and restart the API, workers and ARQ. Keep the MinIO volume until you have checked recordings and documents in the console, then remove it.
  </Step>
</Steps>

## From the bundled MinIO to the bundled SeaweedFS

For an install made before SeaweedFS became the default (`OBJECT_STORE=minio`). MinIO keeps running during the migration: new files go to SeaweedFS while the old ones are still read from MinIO.

<Steps>
  <Step title="Switch new files to SeaweedFS">
    In `.env`: `OBJECT_STORE=seaweedfs` (keep `minio` in `COMPOSE_PROFILES` if you set it by hand), then restart with your usual command (`./remote_up.sh`, the lab kit `--only nimbora`, `sudo ./install.sh` in `deploy/enterprise`). The API creates the `voice-audio` bucket on SeaweedFS at start-up.
  </Step>
  <Step title="Copy and verify">
    ```bash
    docker compose exec api python -m scripts.migrate_object_store copy
    docker compose exec api python -m scripts.migrate_object_store verify
    ```
    With `OBJECT_STORE=seaweedfs` the destination is the bundled SeaweedFS: no `S3_*` setting is needed.
  </Step>
  <Step title="Switch the old files">
    ```bash
    docker compose exec api python -m scripts.migrate_object_store switch   # type BASCULER
    ```
    `/api/v1/health` then shows `legacy_minio_files: 0`. Play a few old recordings in the console.
  </Step>
  <Step title="Retire MinIO">
    `MINIO_RETIRED=true` in `.env` and restart: MinIO is no longer started. Keep its volume for a while, then remove it (`docker volume rm <project>_minio-data`; `nimbora-enterprise_minio_data` for the enterprise stack, whose backup includes it as long as it exists).
  </Step>
</Steps>

## What SeaweedFS runs with

One container, `chrislusf/seaweedfs` (version pinned in `docker-compose.yaml`, `SEAWEEDFS_IMAGE` to override): master, volume server, filer and S3 gateway (`server -s3`), data in the `seaweedfs-data` volume, S3 on port 8333 bound to localhost. Its admin identity comes from the bundled store's keys, which makes the bucket private; anonymous usage statistics are turned off (`-master.telemetry=false`), and the Iceberg and Lance listeners are disabled. The reverse proxy serves `/voice-audio/` from it (nginx `deploy/templates`, Traefik `deploy/lab`, Caddy `deploy/enterprise`). The enterprise stack runs the same image and command on its private network, with no published port and its generated keys.

The `deploy/enterprise` stack and the Helm chart still bundle MinIO: they move to SeaweedFS in a later release, once it is validated on the reference lab.
